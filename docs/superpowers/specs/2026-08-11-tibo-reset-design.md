# Tibo Reset 网站设计规格

## 1. 产品定义

`Tibo Reset` 是一个非官方的 ChatGPT/Codex 额度重置预测仪表盘。它不接入 GPT，也不直接调用 X API；站点定时镜像 `willtiboreset.xyz` 已公开的预测、推文信号、预测历史与模型表现 JSON，用独立设计的中英双语界面帮助用户快速判断 5 小时、24 小时和 48 小时内发生额外全局 hard reset 的概率。

站点必须醒目标明：数据和预测来自第三方公开项目，本站与 OpenAI、Thibault Sottiaux 或参考站无隶属或背书关系，概率仅供娱乐和信息参考。

## 2. 已确认需求

- 项目名称：`Tibo Reset`。
- 本地路径：`D:\桌面\Tibo-Reset`。
- 中文默认，可切换英文；语言选择保存在浏览器本地。
- 功能范围对标参考站：三档概率、预计时间、预测原因、信号源、概率历史、模型表现、提醒和方法说明。
- 视觉重新设计，不复制参考站布局、圣像素材或黑底青色终端风格。
- 不做聊天机器人，不使用 OpenAI API，不使用 X API。
- 预测对象为额外全局 hard reset；普通周刷新、banked reset 和 boost/unlock 不应被表述成同一事件。
- 本地交付包含冷启动验证过的一键启动器。
- 同一套静态站点可以部署到 GitHub Pages，公开站点的数据由 GitHub Actions 定时镜像。

## 3. 视觉与交互

视觉主题为“深夜气象观测站”：深靛蓝背景、珊瑚橙预警色、冰蓝数据线、半透明玻璃卡片和大面积圆形雷达。主视觉使用抽象字母 `T`、扫描环和天气轨迹，不使用真人照片或参考站图像。

桌面首屏包括：

1. 品牌、非官方标签、数据在线状态、最近更新时间和中英文切换。
2. 24 小时主概率圆环，5 小时与 48 小时概率作为辅助读数。
3. 根据阈值生成的行动提示：低概率时“可以安心继续使用”，中等概率时“留意新信号”，高概率时“建议优先使用剩余额度”。
4. 下一次预计重置时间与倒计时。
5. 开启浏览器提醒、复制分享文案两个按钮。

后续区块按顺序为：主要因素、当前信号、24 小时概率轨迹、模型表现、历史重置记录、数据方法与免责声明。移动端改为单列，主概率圆环和操作按钮保持在首屏可见。

## 4. 数据架构

### 4.1 上游来源

同步器读取以下公开 JSON：

- `https://willtiboreset.xyz/data/prediction.json`
- `https://willtiboreset.xyz/data/prediction_history.json`
- `https://willtiboreset.xyz/data/tweets.json`
- `https://willtiboreset.xyz/data/model_performance.json`
- `https://raw.githubusercontent.com/EvanProgramming/willtiboreset/main/data/reset_history.json`

### 4.2 镜像策略

`scripts/sync_data.py` 使用 Python 标准库下载每个文件，先在临时位置解析 JSON，通过结构检查后原子替换 `site/data/` 中的旧文件。任何单个来源失败时保留上一份有效缓存，并把错误写入 `site/data/sync-status.json`；不能用空文件覆盖有效数据。

本地启动器在开站前尝试同步一次。GitHub Actions 在推送、手动触发和定时任务时同步并部署，因此访问者只读取本站镜像，不会对参考站产生每访客一次的额外请求。

### 4.3 前端适配

`site/app.js` 只读取相对路径 `./data/*.json`。它负责：

- 校验并格式化三档概率、下一次时间和预测因素。
- 从推文中分别选择最新的 Tibo、OpenAI、Community 信号。
- 将预测历史降采样后绘制 SVG 折线图。
- 展示上游模型原始表现，并明确标注“上游报告值，不代表本站独立验证”。
- 将 reset history 去重后按时间倒序展示。
- 数据过期超过 90 分钟时显示“数据可能已过期”；同步失败时显示缓存状态。

## 5. 浏览器功能

- 语言切换：默认 `zh-CN`，`localStorage` 保存 `tibo-reset-language`。
- 主题不依赖外部字体或 CDN，避免离线和国内网络失败。
- 提醒：用户主动授权后，当 5h 概率首次超过 50%或 24h 概率首次超过 60%时发送浏览器通知；触发状态保存在本地，概率回落后才允许再次触发。
- 分享：优先调用 Web Share API，不支持时复制中英对应的摘要文本，包含概率、两条原因、更新时间、非官方说明和当前网址。
- 所有上游文本按纯文本插入 DOM，不执行来源 HTML。

## 6. 本地启动与公开部署

`启动 Tibo Reset.cmd` 调用 `scripts/start-site.ps1`。启动脚本先检查 `http://127.0.0.1:4178/health.json` 是否已经是本项目；若是则直接打开，若不是则同步数据、启动隐藏的 Python 静态服务器、等待健康检查成功后打开浏览器。`-NoBrowser` 参数用于自动测试。

公开部署采用 GitHub Pages。`.github/workflows/pages.yml` 在 `main` 推送、手动触发和每 20 分钟计划任务时运行数据同步，再把 `site/` 上传为 Pages artifact。站点所有资源使用相对路径，确保既可运行在 localhost，也可运行在仓库子路径。

## 7. 非目标

- 不声称本站模型比上游模型更准确。
- 不抓取 X 页面、不保存 Cookie、不绕过 X 访问限制。
- 不提供登录、付费、邮件提醒、社区预测市场或自动发帖。
- 不冒充 TiBO，不生成其第一人称对话。
- 不复制参考站代码、版式、插图或品牌视觉；仅使用其明确公开的数据接口并保留来源链接。

## 8. 验收标准

- 中文为首次打开的默认语言，切换英文后刷新仍保持英文。
- 当前公开数据能同步，五个 JSON 均可解析；断网/单源失败时仍能加载缓存并显示降级状态。
- 首页能渲染 5h/24h/48h 概率、更新时间、预计时间、因素、信号、历史图、表现和 reset 历史。
- 分享按钮和通知授权路径无 JavaScript 错误。
- 1440px 桌面与 390px 移动宽度无横向溢出、遮挡或不可点击控件。
- `node --check site/app.js`、同步器测试、静态结构测试全部通过。
- 从无服务器状态运行一键启动器后，健康检查成功且浏览器页面正常；重复运行不会启动第二个服务器。
- GitHub Pages 返回 HTTP 200，公开页能读到本仓库镜像的数据并显示中文界面。
